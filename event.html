ماذا يعني هذا عمليًا؟

هذا النمط (Logon Type 2 + Source 127.0.0.1 + svchost.exe + User32) هو التوقيع الكلاسيكي لشاشة قفل الجهاز (Lock Screen):

  • شخص ما (على الأرجح أنت) حاول فتح قفل الجهاز أو تسجيل الدخول محليًا
  • تم إدخال كلمة مرور خاطئة
  • الطلب جاء من نفس الشاشة/لوحة المفاتيح المتصلة بالجهاز، وليس عبر الشبكة

ما هو Event Viewer (عارض الأحداث)؟

Event Viewer هو أداة مدمجة في نظام ويندوز تعرض سجل تفصيلي لكل ما يحدث على الجهاز: عمليات تسجيل الدخول والخروج، أخطاء النظام والتطبيقات، تنبيهات الأمان، توصيل الأجهزة الخارجية (مثل USB)، وأي حدث يقوم النظام بتسجيله تلقائيًا في الخلفية.

تُقسّم الأحداث داخل الأداة إلى عدة سجلات رئيسية (Logs)، أبرزها:

  • Application — أحداث وأخطاء البرامج المثبتة
  • Security — أحداث الأمان مثل نجاح/فشل تسجيل الدخول (وهو السجل المستخدم في تحليل هذا التقرير)
  • System — أحداث النظام نفسه، مثل تعريف الأجهزة وتشغيل/إيقاف الخدمات
  • Setup — أحداث متعلقة بتثبيت النظام والتحديثات

كل حدث مسجّل له Event ID فريد (مثل 4625 أو 4624)، ووقت حدوثه بالتفصيل، ومصدر العملية، مما يجعله أداة أساسية في التحقيق الأمني وتحليل أي نشاط مشبوه على الجهاز.

💡 لماذا هو مهم؟ لأنه يعطيك سجلًا زمنيًا موثوقًا (Timeline) لكل ما جرى على الجهاز، حتى لو لم تكن حاضرًا وقت حدوثه — وهذا ما يجعله نقطة الانطلاق الأولى في أي تحقيق أمني رقمي.

كيف تصل إلى Event Viewer (عارض الأحداث)

الطريقة الأولى: من شريط البحث اضغط زر ويندوز ⊞ Win، ثم اكتب Event Viewer أو بالعربي "عارض الأحداث"، ثم اضغط Enter.
الطريقة الثانية: أمر Run اضغط Win + R لفتح نافذة Run، ثم اكتب eventvwr.msc واضغط Enter.
الطريقة الثالثة: من Control Panel Control Panel ← System and Security ← Administrative Tools ← Event Viewer.
الوصول لسجل Security داخل عارض الأحداث، من الشجرة على اليسار: Windows Logs → Security.

كيف تنشئ فلتر لعرض الحدث 4625 فقط

افتح سجل Security من الشجرة: Windows Logs → Security.
افتح خيار الفلترة من قائمة Actions على اليمين، اختر Filter Current Log...
أدخل رقم الحدث في حقل <All Event IDs> اكتب: 4625
(اختياري) حدد المدة الزمنية من قائمة Logged اختر مدى زمني مثل "Last 24 hours" أو "Custom range" لتضييق النتائج.
اضغط OK سيعرض السجل الآن فقط الأحداث برقم 4625 (محاولات تسجيل دخول فاشلة).
حفظ الفلتر (اختياري) يمكنك حفظ هذا الفلتر كمهمة مخصصة عبر Actions → Save Filter to Custom View... لإعادة استخدامه لاحقًا بسرعة.
💡 نصيحة يمكنك أيضًا استخدام XML مخصص داخل نفس نافذة الفلترة (تبويب XML) لدمج أكثر من شرط، مثلاً عرض 4625 و4624 معًا لمقارنة محاولات الفشل والنجاح.

استعلام PowerShell لسحب أحداث 4625

بدلًا من الفلترة اليدوية، يمكنك استخدام PowerShell لسحب كل محاولات الفشل بسرعة وتصديرها.

عرض آخر أحداث 4625

Get-WinEvent -FilterHashtable @{
    LogName   = 'Security'
    Id        = 4625
} | Select-Object TimeCreated, Id, Message |
    Format-List

سحب الأحداث ضمن آخر 24 ساعة فقط

Get-WinEvent -FilterHashtable @{
    LogName   = 'Security'
    Id        = 4625
    StartTime = (Get-Date).AddHours(-24)
} | Sort-Object TimeCreated -Descending |
    Format-Table TimeCreated, Id -AutoSize

عرض 4625 و4624 معًا للمقارنة (فشل مقابل نجاح)

Get-WinEvent -FilterHashtable @{
    LogName = 'Security'
    Id      = 4624, 4625
} | Sort-Object TimeCreated -Descending |
    Select-Object TimeCreated, Id |
    Format-Table -AutoSize

تصدير النتائج إلى ملف CSV

Get-WinEvent -FilterHashtable @{
    LogName = 'Security'
    Id      = 4625
} | Select-Object TimeCreated, Id, Message |
    Export-Csv -Path "$env:USERPROFILE\Desktop\failed_logons.csv" -NoTypeInformation -Encoding UTF8
ملاحظة يجب تشغيل PowerShell كمسؤول (Run as Administrator) للوصول الكامل لسجل Security.

تجميع أدوات وتقنيات للكشف عن أنشطة الفلاش ميموري

معرفة دخول وخروج الفلاش ميموري (USB) شيء، ومعرفة هل تم نسخ ملفات منها/إليها شيء آخر تمامًا وأصعب بكثير. خلي نشرح الاثنين:

1️⃣ معرفة أن فلاش ميموري دخل وخرج (سهل نسبيًا)

عبر Event Viewer

افتح eventvwr.msc وراجع هذي السجلات:

السجلالحدثيدل على
SystemEvent ID 20001تثبيت جهاز USB (Device Setup)
SystemEvent ID 2003 / 2010(DriverFrameworks-UserMode) بداية/نهاية الاتصال
Microsoft-Windows-Kernel-PnP/ConfigurationEvent ID 410, 400تعريف الجهاز وإزالته
SecurityEvent ID 6416جهاز إدخال جديد تم التعرف عليه (لو مفعّل Audit)
الأسهل عمليًا الذهاب إلى: Applications and Services Logs → Microsoft → Windows → DriverFrameworks-UserMode → Operational. هذا السجل يعطيك بالضبط وقت التوصيل ووقت الفصل لأي جهاز USB.

عبر PowerShell (أسرع وأدق)

Get-WinEvent -FilterHashtable @{
    LogName = 'System'
    Id = 20001,20003
} | Select-Object TimeCreated, Id, Message | Format-List

عبر الـ Registry (سجل تاريخي دائم حتى لو حُذف الفلاش ميموري قبل فترة طويلة)

HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Enum\USBSTOR

هنا تلقى كل فلاش ميموري اتصل بالجهاز يومًا ما مع الرقم التسلسلي (Serial Number)، حتى لو مو موجودة الحين. لمعرفة آخر وقت اتصال لكل جهاز:

HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Enum\USBSTOR\...\Properties\{83da6326-97a6-4088-9453-a1923f573b29}\0066
أداة جاهزة (أسهل بكثير) أداة USBDeview من NirSoft — مجانية، تعرض لك مباشرة: اسم الفلاش ميموري، الرقم التسلسلي، تاريخ أول وآخر توصيل، وهل هي متصلة الآن أو لا. بدون تعقيد Registry يدوي.

2️⃣ معرفة هل صار نسخ/لصق فعلي (أصعب — Windows لا يسجله افتراضيًا)

⚠ مهم ويندوز لا يسجل تلقائيًا عمليات نسخ الملفات (لا من الفلاش ميموري ولا إليها) إلا إذا تم تفعيل التدقيق مسبقًا.

أ) فعّلت تدقيق الوصول للملفات (Object Access Auditing) مسبقًا

لازم يكون مفعّل قبل حدوث النسخ على المجلد المطلوب مراقبته:

  • secpol.msc → Local Policies → Audit Policy → فعّل "Audit object access"
  • على المجلد المستهدف: Properties → Security → Advanced → Auditing → أضف قاعدة على "Everyone" لـ Read/Write
  • بعدها راقب Event ID 4663 (تم الوصول للكائن) في سجل Security

إذا ما كان هذا مفعّل من قبل، ما راح تلقى دليل مباشر على عملية النسخ نفسها.

ب) آثار غير مباشرة تدل على نشاط ملفات (متوفرة افتراضيًا)

حتى بدون تفعيل Auditing، فيه بقايا (Artifacts) تساعدك تخمّن:

المصدريكشف
RecentDocs في الريجستري (HKCU\...\Explorer\RecentDocs)أسماء آخر ملفات تم فتحها من أي مكان (يشمل الفلاش ميموري)
Jump Lists (%AppData%\Microsoft\Windows\Recent\AutomaticDestinations)ملفات فُتحت مؤخرًا ببرامج معينة
ShellBags (Registry)يثبت أنك تصفحت مجلدًا على الفلاش ميموري، حتى لو حُذف لاحقًا
LNK files في Recent folderكل اختصار يحتوي أحيانًا على الرقم التسلسلي للفلاش ميموري نفسه
$MFT / USN Journal (تحليل جنائي متقدم)يعطي توقيت إنشاء/تعديل/نسخ الملفات على القرص، حتى بدون Auditing — يحتاج أدوات تحليل جنائي مثل MFTECmd أو Autopsy
🎯 خلاصة عملية
  • لمعرفة الدخول/الخروج فقط ← USBDeview أو DriverFrameworks-UserMode Log، وهذا متاح من الآن.
  • لمعرفة نسخ/لصق فعلي حصل في الماضي بدون Auditing مفعّل مسبقًا ← صعب تثبته بشكل قاطع، لكن تقدر تستدل من RecentDocs وShellBags.
  • لو تبي توثيق دقيق من الآن فصاعدًا ← فعّل Object Access Auditing على المجلدات الحساسة والآن راح يسجل كل نسخ/قراءة/كتابة بالتفصيل.
