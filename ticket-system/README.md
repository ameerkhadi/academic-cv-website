# نظامُ التذاكر الإلكترونيّة

> كلُّ طلبٍ أو شكوى يتحوّل إلى تذكرةٍ برقمٍ مرجعيٍّ تُتابَع حتّى الإغلاق —
> بدل أن تضيع بين المكالمات والرسائل المتفرّقة.

نظامٌ عاملٌ بُني ليُشرَح في المحاضرة، لا نموذجًا للعرض: قاعدةُ بيانات،
وصلاحيّات، وسجلٌّ كاملٌ لكلّ ما جرى على التذكرة، وتصعيدٌ آليٌّ عند تجاوز المدّة.

## المسار

```
المواطن ──▶ يفتح شكوى ──▶ رقمٌ مرجعيّ + رمزُ متابعة
                │
        النظامُ يصنّف ويحدّد الإلحاح ويُحيل إلى الشعبة
                │
        الموظّف يعالج ──▶ يردّ ──▶ يُغلق
                │
        تجاوزت المدّة؟ ──▶ تصعيدٌ آليّ ──▶ لوحةُ المدير
                │
        المواطن يتابع برقمه ──▶ يقيّم بعد الإغلاق
```

## القواعدُ المنفَّذة

هي قواعدُ الدائرة المكتوبة، منقولةٌ إلى الكود كما هي في `app/config.py`،
فلا يختلف ما يُشرَح في القاعة عمّا يجري في الخادم.

| الفئة | جهةُ الإحالة |
|---|---|
| تأخير | شعبة التسجيل |
| خطأ بيانات | شعبة التسجيل |
| رفض غير مبرَّر | القسم القانوني |
| سوء تعامل | الموارد البشرية |
| أخرى | شعبة المتابعة |

| درجةُ الإلحاح | متى | مدّةُ الاستجابة |
|---|---|---|
| عالية | تجاوزُ المدّة القانونيّة أو أثرٌ ماليٌّ مباشر | ٢٤ ساعة |
| متوسطة | شكوى عملٍ دون ذلك | ٧٢ ساعة |
| دنيا | استفسارٌ أو طلبُ معلومة | ١٢٠ ساعة |

**التصعيد:** عند بلوغ المدّة تُرفَع التذكرةُ إلى «رئيس القسم» (مستوى ١)،
وعند تجاوزها بنصفها إلى «المدير العام» (مستوى ٢). ولا تُرفَع تذكرةٌ إلى
مستوًى بلغته من قبل، ولا تُصعَّد تذكرةٌ مغلقة.

## التصنيفُ الآليّ

`app/classify.py` يقرأ نصَّ الشكوى فيستنتج الفئةَ ودرجةَ الإلحاح والجهة،
ويكتب في سجلّ التذكرة **سببَ قراره** — فالقرارُ مُراجَعٌ لا صندوقٌ مغلق.

والتنفيذُ محلّيٌّ بلا خدمةٍ خارجيّة، فيعمل على خادمٍ بلا إنترنت، ونتيجتُه
ثابتةٌ بين تشغيلٍ وآخر. وهذا شرطُ القبول في العمل الرسميّ: قرارٌ يُفسَّر
ويتكرّر، ولا يخرج من النصّ بياناتٌ إلى جهةٍ خارجيّة.

ويبقى للموظّف والمدير تعديلُ ما استُنتج، ويُثبَّت التعديلُ في السجلّ.

## التشغيلُ محلّيًّا

```sh
pip install -r requirements.txt
python3 -m app.seed --demo --password=اختر-كلمة-مرور   # حساباتٌ وبياناتُ عرض
python3 run.py                                          # http://127.0.0.1:8000
```

الحسابات: `manager` (مدير) و`tasjeel` و`qanoni` و`mawarid` و`mutabaa` (موظّفو الشُّعَب).

## التنصيبُ على خادم لينكس

```sh
sudo TK_ADMIN_PW='كلمة-مرور-قويّة' deploy/install.sh
```

يُنشئ مستخدمَ خدمةٍ غيرَ مُسجِّلِ دخول، وبيئةً افتراضيّة، ومفتاحَ توقيعٍ
عشوائيًّا، ووحدةَ `systemd` مقيَّدةَ الصلاحيّات. ويبقى على المسؤول: نسخُ
`deploy/nginx.conf` وتعديلُ النطاق، ثمّ شهادةُ TLS، ثمّ الجدارُ الناريّ.

**الخادمُ لا يُعرَّض للإنترنت مباشرةً**: يستمع على `127.0.0.1` ويمرّ الطلبُ
عبر nginx الذي يُنهي TLS.

## ما رُوعي في الأمن

- كلماتُ المرور مُجزَّأةٌ بـ PBKDF2-SHA256 بمئتَي ألف دورة، ولا تُخزَّن صريحةً.
- الجلساتُ في قاعدة البيانات، والكعكةُ `HttpOnly` و`SameSite=Lax`، و`Secure` تحت TLS.
- كلُّ طلبٍ مُغيِّرٍ للحالة يحمل رمزًا يمنع التزوير، والمقارنةُ على البايتات
  فلا تُسقِط قيمةٌ غيرُ لاتينيّةٍ الخادمَ.
- كلُّ استعلامٍ بمعاملاتٍ مربوطة، فلا مجالَ لحقن SQL.
- حدٌّ لعدد الشكاوى من العنوان الواحد.
- الموظّف لا يرى إلّا تذاكرَ شعبته، وإعادةُ الإحالة وتغييرُ الإلحاح للمدير وحده.
- `noindex` على الصفحات كلِّها، ولا يُفهرِسها محرّكُ بحث.

**ما لم يُنفَّذ بعدُ** ويلزم قبل التشغيل الحقيقيّ: نسخٌ احتياطيٌّ مجدول،
وسجلُّ دخولٍ مركزيّ، وحذفُ البيانات بعد مدّةِ حفظٍ معلومة.

## البنية

```
app/config.py    القواعدُ والثوابت — موضعُ أيّ تعديلٍ في سياسة الدائرة
app/db.py        المخطّطُ وتجزئةُ كلمات المرور وتوليدُ الأرقام المرجعيّة
app/classify.py  التصنيفُ الآليّ وتفسيرُ قراره
app/service.py   منطقُ العمل: الإنشاء والمعالجة والتصعيد والمؤشّرات
app/auth.py      الجلساتُ ومنعُ التزوير
app/main.py      المسارات والصفحات
app/arabic.py    الأرقامُ الهنديّةُ وتمييزُ العدد
tests/           ٢٩ اختبارًا: التصنيف، والمسار الكامل، والتصعيد، والصلاحيّات
```
