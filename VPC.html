SECTION 1 · NETWORKING BASICS
What is a Computer Network?
A computer network
Two or more devices connected to share resources. Like a group of offices in the same building sharing a printer and file server.Example: Your university lab — all PCs connected to one printer and one internet line
 is two or more client machines connected together to share resources. A network can be logically partitioned into subnets
A smaller division within a larger network. Like dividing a building floor into departments, each with their own area.Example: VPC 10.0.0.0/16 split into 10.0.1.0/24 (web) and 10.0.2.0/24 (database)
. Networking requires a router or switch
A router connects different networks and forwards packets between them. A switch connects devices within the same network.Example: Your home WiFi router connects your devices to your ISP's network
 to connect all clients and enable communication.

CIDR NOTATION
Classless Inter-Domain Routing (CIDR)
CIDR
A method for allocating IP addresses and routing. Replaces the old Class A/B/C system with flexible prefix lengths.Example: 192.168.1.0/24 means the first 24 bits are the network — 256 total addresses
 is expressed as: IP address / prefix length. The prefix tells you how many bits are fixed (network) — the remaining bits are flexible (hosts).

/24 — Common Subnet
256 total IPs, 251 usable. Most common VPC subnet size.

Example: 10.0.1.0/24 — a typical web server subnet
/32 — Single Host
Exactly 1 IP address. Used in Security Group rules to allow only one specific machine.

Example: 203.0.113.5/32 — allow only this admin's IP
0.0.0.0/0 — All Internet
Every bit is flexible — represents the entire internet. Used in route tables to send all traffic to IGW.

Example: Route 0.0.0.0/0 → igw-id

SECTION 2 · AMAZON VPC
What is Amazon VPC?
Amazon Virtual Private Cloud
A logically isolated network within AWS where you launch your resources. Think of it as your own private data center inside AWS.Example: Create VPC 10.0.0.0/16 in us-east-1, then launch EC2 instances and RDS databases inside it
 (Amazon VPC) lets you provision a logically isolated section of the AWS Cloud. You have complete control over your virtual networking environment.
🔒
Logically Isolated
Your VPC is completely isolated from other AWS customers. Traffic from your EC2 instances cannot reach another customer's resources unless you explicitly allow it.
Example: Bank A and Bank B both use AWS — they cannot see each other's traffic or resources
🌍
Regional Resource
A VPC belongs to one AWS Region but can span multiple Availability Zones within that region. This enables high availability.
Example: One VPC in us-east-1 with subnets in us-east-1a, 1b, and 1c
⚙️
Full Control
You choose the IP range, create subnets, configure route tables, and set up network gateways — just like an on-premises network.
Example: Choose 10.0.0.0/16, create public 10.0.1.0/24 and private 10.0.2.0/24
🛡️
Multi-Layer Security
Use Security Groups (instance-level) and Network ACLs (subnet-level) to create defense-in-depth for your resources.
Example: SG allows port 443 inbound; NACL blocks specific IP ranges

Choosing Your VPC CIDR Block
When you create a VPC, you assign an IPv4 CIDR block. ⚠️ This cannot be changed after creation — choose carefully!
/16
Maximum VPC Size
2¹⁶ = 65,536 addresses. Best for large enterprise environments.
Example: 10.0.0.0/16
/24
Common Subnet Size
2⁸ = 256 addresses (251 usable). Standard size for most subnets.
Example: 10.0.1.0/24
/28
Minimum VPC Size
2⁴ = 16 addresses (11 usable). Very small — limited scalability.
Example: 10.0.0.0/28
⚠️ Subnet CIDR Rules: Subnets within a VPC cannot have overlapping CIDR blocks. You cannot have duplicate IP addresses in the same VPC. Plan your IP space carefully before creation!

PUBLIC IP ADDRESS TYPES
Public IPv4 vs Elastic IP

Public IPv4 Address

Automatically assigned via subnet settings
Changes when instance is stopped & restarted
Tied to the instance lifecycle
No additional cost while instance runs
Example: Start EC2 → gets 54.210.1.5. Stop it. Start again → gets 54.210.2.9 (different!)

Elastic IP Address (EIP)

Static — never changes, even after stop/start
Associated with your account, not the instance
Can be remapped to another instance instantly
⚠️ Charges apply when NOT associated with a running instance
Example: Fintech app with IP 54.210.1.5 whitelisted by 50 banks. Use EIP to keep the same IP even if you replace the EC2 instance.

An Elastic Network Interface

A virtual NIC (network interface card) that you can attach/detach from EC2 instances. Think of it like a physical network card you can hot-swap between servers.Example: Move ENI from failed server to new server — traffic instantly redirects, no IP change needed
is a virtual network card that you can attach or detach from an instance in a VPC.


Attributes Follow ENI
When you move an ENI to another instance, all its attributes (IP addresses, MAC address, Security Groups) move with it — in one step
Primary Interface
Every EC2 instance has a default (primary) ENI. You cannot detach the primary ENI from a running instance
Multiple ENIs
You can attach additional ENIs. Number of ENIs per instance depends on the instance type (e.g., t3.medium supports 3 ENIs)
💡 Use case: Attach an Elastic IP to an ENI instead of directly to the instance. If the instance fails, detach the ENI and attach it to a replacement instance. The EIP and all other attributes follow the ENI — no reconfiguration needed at the bank/partner side.
ROUTE TABLES
Route Tables & Routes
A route table
A set of rules (routes) that determine where network traffic from your subnet is directed. Every subnet must be associated with exactly one route table.Example: Public subnet route table: 0.0.0.0/0 → igw-id (sends all internet traffic to IGW)
 contains rules called routes, each with a Destination (CIDR) and a Target (where to send traffic).
📗 PUBLIC SUBNET ROUTE TABLE
| Destination | Target | |----------------|-----------------| 10.0.0.0/16 local ← VPC internal 0.0.0.0/0 igw-0abc12345 ← Internet!
The 0.0.0.0/0 → igw-id route is what makes a subnet PUBLIC. Without it, the subnet is effectively private.
🔒 PRIVATE SUBNET ROUTE TABLE
| Destination | Target | |----------------|-----------------| 10.0.0.0/16 local ← VPC internal 0.0.0.0/0 nat-0xyz98765 ← NAT GW only
The 0.0.0.0/0 → nat-gw route allows outbound-only internet. No inbound from internet possible.
Built-in Local Route
Every route table automatically includes a local route for the VPC CIDR. This route cannot be deleted. It enables all instances within the VPC to communicate with each other.
One Route Table Per Subnet
A subnet can be associated with only one route table at a time. However, one route table can serve multiple subnets.
Main Route Table
Every VPC has a main route table that automatically applies to all subnets not explicitly associated with another table. Be careful with changes to the main table.

🔑 Section 2 Key Takeaways

  • A VPC is a logically isolated section of the AWS Cloud — dedicated to your account
  • A VPC belongs to one Region and requires a CIDR block (range: /16 max to /28 min)
  • A VPC is subdivided into subnets — each subnet belongs to ONE Availability Zone
  • AWS reserves 5 IP addresses per subnet: .0 (network), .1 (router), .2 (DNS), .3 (future), .255 (broadcast)
  • Route tables control traffic — every subnet must have one; the local route cannot be deleted
  • Elastic IPs are static — tied to your account; charges apply when unused

SECTION 3 · VPC NETWORKING
Internet Gateway (IGW)
An internet gateway
A scalable, redundant, highly available VPC component that allows communication between instances in your VPC and the internet. One IGW per VPC.Example: Attach igw-0abc12345 to your VPC, then add 0.0.0.0/0 → igw-0abc12345 to your public subnet route table
 serves two purposes: (1) provides a target in VPC route tables for internet-routable traffic, and (2) performs NAT for instances with public IPv4 addresses.
ANIMATED INTERNET GATEWAY TRAFFIC FLOW
💡 Two-step process to make a subnet public: (1) Create & attach an Internet Gateway to your VPC. (2) Add a route in the subnet's route table: 0.0.0.0/0 → igw-id. Both steps are required — the IGW alone is not enough.
NAT GATEWAY
Network Address Translation Gateway
A NAT gateway
Allows private instances to initiate outbound connections to the internet (for updates, API calls) while preventing the internet from initiating inbound connections to those instances.Example: RDS database downloads security patches via NAT — but no one from internet can connect to the DB directly
 enables instances in a private subnet to reach the internet, while the internet cannot initiate connections back to those instances.
ANIMATED NAT GATEWAY FLOW — private instance downloads updates

✅ NAT Gateway (Recommended)

Fully managed by AWS — no maintenance
High availability within an AZ
Scales automatically up to 100 Gbps
Must be in a public subnet with Elastic IP
One NAT GW per AZ recommended for HA
Use case: Private EC2 instances downloading OS patches, Lambda accessing external APIs, private databases calling AWS services

⚙️ NAT Instance (Legacy)

Self-managed EC2 instance
You manage availability & failover
Limited bandwidth by instance type
Must disable source/dest check
More complex configuration required
⚠️ AWS recommendation: Use NAT Gateway for new deployments. NAT instances are legacy and require significantly more administrative effort.
  1. Create a NAT Gateway — specify the public subnet where it should reside
  2. Allocate and associate an Elastic IP address to the NAT Gateway
  3. Update the private subnet route table: add route 0.0.0.0/0 → nat-gw-id
  4. Verify private instances can now reach the internet (outbound only)
# AWS CLI commands to set up NAT Gateway # Step 1: Allocate Elastic IP aws ec2 allocate-address --domain vpc # Returns: AllocationId = eipalloc-0abc12345 # Step 2: Create NAT Gateway in public subnet aws ec2 create-nat-gateway \ --subnet-id subnet-public-0123 \ --allocation-id eipalloc-0abc12345 # Returns: NatGatewayId = nat-0xyz98765 # Step 3: Update private subnet route table aws ec2 create-route \ --route-table-id rtb-private-456 \ --destination-cidr-block 0.0.0.0/0 \ --nat-gateway-id nat-0xyz98765

🔑 Section 3 Key Takeaways

  • Internet Gateway = allows bidirectional traffic between VPC and internet; attach to VPC + add route 0.0.0.0/0 → igw-id
  • NAT Gateway = outbound-only internet for private instances; sits in public subnet with Elastic IP
  • NAT Gateway is fully managed by AWS — preferred over NAT Instances for production use
  • For high availability: deploy one NAT Gateway per Availability Zone

Highly available and scalable DNS web service — the backbone of AWS-based domain management
SECTION 5 · AMAZON ROUTE 53
What is Amazon Route 53?
Amazon Route 53
Named after DNS port 53. A highly available, scalable cloud DNS (Domain Name System) web service. Translates domain names like "example.com" into IP addresses.Example: User types "myshop.com" → Route 53 returns IP 54.210.1.5 → browser connects to that server
 is a highly available and scalable DNS web service. It connects user requests to infrastructure running in AWS and can also route users to infrastructure outside AWS.

Routing Policies

Amazon CloudFront
A fast Content Delivery Network (CDN) that securely delivers data, videos, and APIs globally with low latency
SECTION 6 · AMAZON CLOUDFRONT
What is Amazon CloudFront?
Amazon CloudFront
A global Content Delivery Network (CDN) service that speeds up distribution of your web content by caching copies at Edge Locations closest to your users.Example: Your website's images are cached in Frankfurt, Tokyo, and São Paulo — users in each region get content from the nearest edge, not your origin server in Virginia
 is a fast CDN service that securely delivers data, videos, applications, and APIs to customers globally with low latency and high transfer speeds.
ANIMATED CLOUDFRONT GLOBAL DISTRIBUTION
⚡
Low Latency
Content cached at edge locations near users. A user in Iraq gets content from Bahrain edge, not Virginia origin — milliseconds vs seconds.
Example: Without CDN: 300ms. With CloudFront: 15ms from nearest edge
🔒
Security Built-in
Integrates with AWS WAF, AWS Shield, and ACM for HTTPS certificates. Protects against DDoS attacks at the edge level.
Example: Free TLS certificate via ACM for your CloudFront distribution
🔗
Integrations
Works with S3, EC2, ALB, Lambda@Edge, Route 53, and API Gateway as origin sources.
Example: CloudFront → S3 static website → Route 53 custom domain → HTTPS via ACM

🔑 Section 6 Key Takeaways

  • CloudFront is a CDN that caches content at 450+ global Edge Locations
  • Users get content from the nearest edge — dramatically reducing latency
  • Integrates natively with S3, EC2, ALB, Lambda, and Route 53
  • Built-in security: DDoS protection, WAF integration, HTTPS/TLS support
