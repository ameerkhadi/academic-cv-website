Introduction to Cloud Computing and Shared Responsibility

Before we can secure the cloud, we must agree on what the cloud is, who runs which part of it, and therefore who is responsible when something goes wrong.

🎯 By the end of this lecture you can:
  1. State the NIST definition and its 5 essential characteristics.
  2. Classify a service as IaaS, PaaS or SaaS — and explain why.
  3. Compare public, private, community and hybrid clouds.
  4. Name the major providers and match their equivalent services.
  5. Draw the shared responsibility model and use it to decide who is at fault in a real incident.
1The NIST definition

The most widely used definition comes from the US National Institute of Standards and Technology, NIST SP 800-145 (2011):

“Cloud computing is a model for enabling ubiquitous, convenient, on-demand network access to a shared pool of configurable computing resources (e.g., networks, servers, storage, applications, and services) that can be rapidly provisioned and released with minimal management effort or service provider interaction.”

NIST then describes the cloud with a 5 – 3 – 4 structure:

2The five essential characteristics

If a service lacks one of these, NIST would not call it “cloud” — it is just a remote server.

🖱️
On-demand self-serviceYou create a server yourself from a web console or API — no email to an admin, no waiting.
🌐
Broad network accessReachable over the network with standard clients: browser, phone, laptop, CLI.
🧩
Resource poolingOne physical machine serves many customers (multi-tenancy); you don't know or control the exact hardware.
📈
Rapid elasticityScale up for exam day, scale down after — capacity appears “unlimited”.
🧾
Measured serviceUsage is metered and billed: CPU-hours, GB stored, GB transferred.
🔎 Real example from this course's lecturer: my sensor platform runs on a DigitalOcean server. I created it in one minute from the web panel (self-service), it is reached from any phone (broad access), it shares a physical host in Frankfurt with other customers (pooling), I can resize it to more CPUs with one click (elasticity), and the bill shows the exact hours used (measured). By contrast, a server in the university machine room that needs a request to IT is not self-service.
⚠️ Security angle — why this matters for us: every characteristic creates a risk. Self-service → anyone with stolen credentials can create (or delete) resources. Broad access → the management console is on the Internet. Pooling → a bug in the hypervisor could leak data between tenants. Elasticity → an attacker can run up a huge bill (crypto-mining). Measured → billing data reveals what you run.
بالعربي: الحوسبة السحابية حسب NIST هي أن تحصل على موارد حاسوبية (خوادم، تخزين، شبكات، تطبيقات) عند الطلب وبنفسك، عبر الشبكة، من مجمّع مشترك بين زبائن كثيرين، تكبر وتصغر بسرعة، وتدفع حسب الاستهلاك. القاعدة للحفظ: ٥ خصائص – ٣ نماذج خدمة – ٤ نماذج نشر.
3Service models — what exactly do you rent?

Think of a computer as a stack of layers. The service model tells you where the provider stops and you start.

🏗️
IaaS — Infrastructure as a ServiceYou rent virtual machines, disks and networks. You install and patch the operating system and everything above it.
Examples: AWS EC2, Azure Virtual Machines, Google Compute Engine, DigitalOcean Droplets.
🛠️
PaaS — Platform as a ServiceYou upload code; the provider runs the OS, runtime and scaling.
Examples: Google App Engine, Azure App Service, AWS Elastic Beanstalk, Heroku, Google Apps Script.
📦
SaaS — Software as a ServiceYou just use a finished application in the browser.
Examples: Gmail, Microsoft 365, Google Classroom, Zoom, Salesforce.

💡 Rule of thumb: the higher you go (IaaS → PaaS → SaaS), the less you manage — but also the less you control and the more you must trust the provider. Security work does not disappear; it moves to configuration, identities and data.
🔎 Classify the lecturer's own apps: the sensor platform on a DigitalOcean droplet = IaaS (I patch Ubuntu, nginx and the firewall). The AI-course platform built on Google Sheets + Apps Script = PaaS (I write the code, Google runs it). The university email in Gmail = SaaS (I only manage my password, 2-step verification and who I share with).

Other “as-a-Service” names you will meet

FaaS / serverless (AWS Lambda, Azure Functions, Google Cloud Run functions) — you upload a single function and pay per call; usually grouped with PaaS. CaaS — containers as a service (Kubernetes services such as EKS, AKS, GKE). DBaaS — managed databases (Amazon RDS, Azure SQL Database, Cloud SQL). SECaaS — security as a service (cloud firewalls, e-mail filtering).

بالعربي: IaaS = تستأجر الخادم الافتراضي وتدير نظام التشغيل وما فوقه (مثل EC2 أو Droplet). PaaS = ترفع الكود فقط والمزوّد يدير النظام والتشغيل (مثل App Engine وApps Script). SaaS = تستخدم برنامجًا جاهزًا (مثل Gmail). كلّما صعدنا قلّ ما نديره وقلّت سيطرتنا — لكن البيانات تبقى مسؤوليتنا دائمًا.
4Deployment models — who shares the cloud?

The service model says what you rent; the deployment model says who else uses the same infrastructure and who owns it.

ModelWho uses itStrengthsSecurity concerns
PublicAny customer (multi-tenant)Cheap to start, huge scale, global regions, mature security toolsShared hardware, data outside your country, misconfiguration exposed to the Internet
PrivateOne organizationFull control, data stays on-site, custom policiesYou do all the security work; expensive; often weaker patching and monitoring
CommunitySeveral organizations with common requirementsShared cost, common compliance rulesTrust between members; who governs; one weak member affects all
HybridMix of the aboveKeep sensitive data private, use public for scaleThe connection (VPN, identity federation) becomes a target; two sets of policies to keep consistent
🔎 Iraqi example: the university's own server room, reachable only through the university VPN, behaves like a private cloud (if it offers self-service). The same lecturer also rents a server in Frankfurt from DigitalOcean — public cloud. When an application keeps student records on the university server but sends anonymous load to the public server, that is a small hybrid setup. A shared data centre run by the Ministry of Higher Education for all universities would be a community cloud.
⚠️ Data sovereignty: on a public cloud your data physically sits in a region (e.g. Frankfurt, Bahrain, UAE). Laws of that country apply to it. For government or health data, check where the region is before you upload.
بالعربي: العامّة مفتوحة لأي زبون (AWS، Azure، Google). الخاصّة لمؤسسة واحدة فقط (مثل خادم الجامعة). المجتمعيّة تشترك فيها مجموعة مؤسسات لها نفس المتطلبات (مثل الجامعات). الهجينة خليط متّصل: البيانات الحساسة داخلًا والباقي في العامّة — ونقطة الاتصال بينهما تصبح هدفًا للمهاجم.
5Major cloud providers

Three “hyperscalers” dominate the market: Amazon Web Services (AWS) is the largest, followed by Microsoft Azure and Google Cloud; together they hold roughly two-thirds of the global market. Other important players: Alibaba Cloud, Oracle Cloud, IBM Cloud, and smaller developer-friendly providers such as DigitalOcean, Linode/Akamai and Hetzner.

☁️ AWSLaunched 2006 (S3, EC2). Largest service catalogue. Middle-East regions: Bahrain, UAE.
☁️ Microsoft AzureStrong with organizations already using Windows, Active Directory and Microsoft 365. Regions in UAE and Qatar.

How to choose (security view)

  • Region / data location — where will the data physically live?
  • Certifications — ISO/IEC 27001, SOC 2, CSA STAR: independent proof the provider secures its part.
  • Identity features — multi-factor authentication, fine-grained roles, single sign-on.
  • Logging & monitoring — can you see who did what, when?
  • Encryption & keys — at rest, in transit, and who holds the keys.
  • Exit plan — can you move your data out (avoid vendor lock-in)?
بالعربي: أكبر ثلاثة مزوّدين: AWS ثم Azure ثم Google Cloud، ومعهم Alibaba وOracle وIBM وDigitalOcean. الخدمات نفسها بأسماء مختلفة (EC2 = Virtual Machines = Compute Engine). تعلّم المفهوم مرّة واحدة وطبّقه على أي مزوّد، واختر المزوّد حسب موقع البيانات والشهادات وإدارة الهويّات والسجلات والتشفير.
6The shared responsibility model

In the cloud, security is a partnership. The provider secures some layers, the customer secures the rest — and the line moves with the service model.

AWS summarises it as: the provider is responsible for security “of” the cloud; the customer is responsible for security “in” the cloud.

💡 The three rows that never move: your data, your identities and your devices are always the customer's job — even in SaaS. Industry analysts (Gartner) have long warned that the large majority of cloud security failures are the customer's fault, mostly misconfiguration and weak identity control.

Real incidents — whose fault?

Capital One, 2019An attacker abused a misconfigured web-application firewall running on the bank's AWS servers and stole data on about 100 million customers. AWS infrastructure was not breached — the configuration was the customer's. → Customer side.
Public storage bucketsAgain and again, companies leave S3 / Blob buckets set to “public” and expose millions of records. The provider gives private-by-default settings and warnings. → Customer side.
Hardware flaws (Spectre/Meltdown, 2018)CPU bugs could leak memory between virtual machines on the same host. Providers had to patch hypervisors and hosts; IaaS customers also had to patch their own guest OS. → Shared.

Same incident, different model

“A critical vulnerability is published in the Linux kernel.” Who must patch?

  • IaaS (your EC2 / Droplet): you — log in and update the OS.
  • PaaS (App Engine, Apps Script): the provider patches the platform; you check your own code and libraries.
  • SaaS (Gmail): the provider — you do nothing except keep your account secure.
بالعربي: الأمن في السحابة شراكة: المزوّد يحمي «السحابة نفسها» (المباني، العتاد، الشبكة، الطبقة الافتراضية)، والزبون يحمي «ما يضعه داخلها». الحدّ يتحرّك حسب النموذج: في IaaS أنت تحدّث نظام التشغيل، وفي SaaS لا. لكن ثلاثة أشياء دائمًا عليك: بياناتك، وحساباتك وكلمات مرورك، وأجهزتك. أغلب الاختراقات الحقيقية (مثل Capital One) سببها إعدادات خاطئة من الزبون، لا اختراق المزوّد.

⚠️ الزاوية الأمنيّة — لماذا يهمّنا هذا: كلّ خاصيّةٍ تفتح خطرًا. الخدمة الذاتيّة ← من يسرق كلمة المرور يستطيع إنشاء الموارد أو حذفها. الوصول الواسع ← لوحة الإدارة موجودة على الإنترنت. التجميع ← ثغرةٌ في المشرف الافتراضيّ قد تسرّب بياناتٍ بين الزبائن. المرونة ← المهاجم قد يرفع فاتورتك (تعدين العملات). القياس ← بيانات الفوترة تكشف ما تشغّله.
٣نماذج الخدمة — ماذا تستأجر بالضبط؟

تخيّل الحاسوب طبقاتٍ فوق بعضها. نموذج الخدمة يحدّد أين يتوقّف المزوّد وأين تبدأ أنت.

الحادثة نفسها في نماذج مختلفة

«أُعلنت ثغرةٌ خطيرة في نواة Linux.» مَن يجب أن يحدّث؟

  • IaaS (خادمك في EC2 أو Droplet): أنت — تدخل وتحدّث نظام التشغيل.
  • PaaS (App Engine، Apps Script): المزوّد يحدّث المنصّة؛ وأنت تراجع كودك ومكتباتك.
  • SaaS (Gmail): المزوّد — وأنت لا تفعل شيئًا سوى حماية حسابك.

Multiple choice

1. Which of the following is not one of the five NIST essential characteristics of cloud computing?

a)Rapid elasticity
b)Measured service
c)Data encryption
d)Resource pooling

Reason: NIST SP 800-145 lists exactly five characteristics: on-demand self-service, broad network access, resource pooling, rapid elasticity and measured service. Encryption is a security control we add, not a defining property of the cloud.
Why not the others: «a» is characteristic ④. «b» is characteristic ⑤ — usage is metered and billed. «d» is characteristic ③ — multi-tenancy.

2. A company rents virtual machines from a provider and installs its own operating system, web server and database. This service model is:

a)SaaS
b)PaaS
c)IaaS
d)Community cloud

Reason: Renting raw VMs and managing the OS and everything above it is the definition of Infrastructure as a Service (e.g. AWS EC2, DigitalOcean Droplets).
Why not the others: «a» in SaaS you would only use a finished application — no OS to install. «b» in PaaS the provider runs the OS and runtime; you would only upload code. «d» is a deployment model (who shares the cloud), not a service model.

3. In which model does the customer manage the fewest layers?

a)On-premises
b)IaaS
c)PaaS
d)SaaS

Reason: In SaaS the provider runs everything up to the application; the customer keeps only its data, users/accounts and devices.
Why not the others: «a» the customer manages every layer, including the building. «b» the customer still manages OS, runtime, apps and data. «c» the customer still manages the application and data.

4. Several universities share one cloud infrastructure built for their common academic and legal requirements. This is a:

a)Public cloud
b)Private cloud
c)Community cloud
d)Hybrid cloud

Reason: A community cloud is shared by a specific group of organizations with common concerns (mission, compliance, security requirements).
Why not the others: «a» is open to any customer, not a defined group. «b» serves one organization only. «d» means connecting two different models, e.g. private + public.

5. The Microsoft Azure service equivalent to Amazon S3 (object storage) is:

a)Azure Functions
b)Blob Storage
c)Microsoft Entra ID
d)AKS

Reason: Amazon S3 ⇄ Azure Blob Storage ⇄ Google Cloud Storage — all three are object storage.
Why not the others: «a» is serverless functions (≈ AWS Lambda). «c» is identity and access management (≈ AWS IAM). «d» is managed Kubernetes (≈ AWS EKS).

6. Under the shared responsibility model, which item is always the customer’s responsibility, in every service model?

a)Patching the hypervisor
b)Physical security of the data centre
c)Classifying and protecting its own data
d)Replacing failed hard disks

Reason: Data, identities (accounts/passwords/MFA) and the users’ own devices stay with the customer in IaaS, PaaS and SaaS.
Why not the others: «a» the virtualization layer belongs to the provider in IaaS, PaaS and SaaS. «b» guards, cameras and access to the building are the provider’s. «d» physical hardware is always the provider’s.

7. “One physical server hosts virtual machines belonging to many different customers.” Which characteristic is this?

a)Broad network access
b)Resource pooling (multi-tenancy)
c)On-demand self-service
d)Measured service

Reason: Resource pooling means the provider’s resources serve multiple consumers (multi-tenant model), assigned dynamically.
Why not the others: «a» is about reaching the service over the network from many device types. «c» is about creating resources yourself without asking an administrator. «d» is about metering and billing usage.

8. In the Capital One breach (2019), about 100 million customer records were stolen from data stored in AWS. The root cause was:

a)A failure in AWS data-centre security
b)A misconfiguration on resources the bank itself ran in AWS
c)A natural disaster in the data centre
d)A bug in the S3 service code

Reason: The attacker exploited a misconfigured web-application firewall on the bank’s own servers and over-permissive access. AWS infrastructure was not breached — a classic “security in the cloud” failure.
Why not the others: «a» no AWS facility or hardware was compromised. «c» there was no physical event involved. «d» the S3 service itself worked as designed; the permissions were the customer’s.

9. A university keeps student records on its own servers but moves its public website to a public cloud, connected through a VPN. This is a:

a)Private cloud
b)Hybrid cloud
c)Community cloud
d)Public cloud

Reason: Two different deployment models (private + public) connected and used together = hybrid. The VPN link becomes an important attack surface.
Why not the others: «a» would keep everything on the university’s own infrastructure. «c» requires several organizations sharing one infrastructure. «d» would put everything on the provider’s shared infrastructure.

10. A critical vulnerability is announced in the Linux kernel. Who must patch it for an application running on Google App Engine (PaaS)?

a)The customer, by logging in to the server
b)The provider (Google)
c)Nobody — PaaS has no operating system
d)The end users of the application

Reason: In PaaS the provider manages the OS and runtime, so Google patches the kernel. The customer still secures its own code and third-party libraries.
Why not the others: «a» would be correct for IaaS (e.g. EC2), not PaaS. «c» every platform runs on an OS; you just don’t manage it. «d» end users have no access to the platform at all.

True or False

1. In SaaS, the customer is responsible for patching the operating system.

False

Reason: The SaaS provider manages and patches everything up to the application. The customer manages data, accounts and devices.

2. Moving to the cloud transfers all security responsibility to the provider.

False

Reason: Responsibility is shared. Data, identities and configuration always stay with the customer — and most real breaches happen exactly there.

3. A hybrid cloud connects a private environment with a public cloud so they work together.

True

Reason: That is the NIST meaning of hybrid: two or more distinct infrastructures bound together.

4. Rapid elasticity means capacity can be scaled up and down quickly, often automatically.

True

Reason: To the consumer the capacity often appears unlimited and can be added or released at any time.

5. A server in the university machine room that you can only get by writing a request to IT is a cloud service according to NIST.

False

Reason: It lacks on-demand self-service (and usually measured service), so it is a hosted server, not cloud in the NIST sense.

6. AWS describes the split as: the provider is responsible for security “of” the cloud, the customer for security “in” the cloud.

True

Reason: This is the wording of the AWS shared responsibility model.

Short answer — model answers

1. Write the NIST definition of cloud computing in your own words (2–3 lines) and list the five essential characteristics.

Model answer: Cloud computing gives on-demand access, over the network, to a shared pool of configurable computing resources that can be provisioned and released quickly with minimal management effort. Characteristics: ① on-demand self-service ② broad network access ③ resource pooling ④ rapid elasticity ⑤ measured service.

Marking guide: Marks for: “on-demand”, “network access”, “shared pool”, “rapid provisioning/release” in the definition; one mark per characteristic.

2. Give one example each of IaaS, PaaS and SaaS. For each, state one security task that stays with the customer.

Model answer: IaaS — AWS EC2: patch the guest OS and restrict the security group (e.g. no SSH open to 0.0.0.0/0). PaaS — Google App Engine: secure your own code and update third-party libraries; control who can deploy. SaaS — Gmail / Microsoft 365: strong password + 2-step verification; control sharing of documents.

Marking guide: Any correct example is accepted if the customer task matches the model: OS work only for IaaS; code/libraries for PaaS; accounts, data and sharing for all three.

3. A hospital in Baghdad wants to store patient records and also run a public appointment-booking website. Recommend a deployment model and justify it from a security point of view.

Model answer: Hybrid cloud. Patient records (highly sensitive health data, legal requirements, data should stay in Iraq) stay in a private cloud the hospital controls. The public booking site runs on a public cloud for availability and scaling, holding only minimal data (name, time). Security focus: a protected link between the two (VPN, strong identity, least privilege), encryption of data in transit and at rest, and logging/monitoring on both sides.

Marking guide: A pure-public answer can earn partial marks if it addresses region/data location, encryption and access control; a pure-private answer if it addresses availability of the public site.

الاختيار من متعدّد

١. أيٌّ ممّا يلي ليس من الخصائص الأساسيّة الخمس للحوسبة السحابيّة حسب NIST؟

أ)المرونة السريعة
ب)الخدمة المَقيسة
ج)تشفير البيانات
د)تجميع الموارد

التعليل: تذكر الوثيقة NIST SP 800-145 خمس خصائص بالضبط: الخدمة الذاتيّة عند الطلب، والوصول الواسع عبر الشبكة، وتجميع الموارد، والمرونة السريعة، والخدمة المَقيسة. التشفير ضابطٌ أمنيّ نضيفه، وليس صفةً تعرّف السحابة.
لماذا ليست الخيارات الأخرى: «أ» هي الخاصيّة ④. «ب» هي الخاصيّة ⑤ — الاستهلاك يُقاس ويُحاسَب. «د» هي الخاصيّة ③ — تعدّد المستأجرين.

٢. شركةٌ تستأجر أجهزةً افتراضيّة من مزوّد، وتثبّت عليها نظام التشغيل وخادم الويب وقاعدة البيانات بنفسها. نموذج الخدمة هو:

أ)SaaS
ب)PaaS
ج)IaaS
د)سحابة مجتمعيّة

التعليل: استئجار أجهزةٍ افتراضيّة وإدارة نظام التشغيل وكلّ ما فوقه هو تعريف البنية التحتيّة كخدمة (مثل AWS EC2 وDigitalOcean Droplets).
لماذا ليست الخيارات الأخرى: «أ» في SaaS تستخدم تطبيقًا جاهزًا فقط — لا نظام تشغيل تثبّته. «ب» في PaaS المزوّد يدير نظام التشغيل وبيئة التشغيل؛ وأنت ترفع الكود فقط. «د» هي نموذج نشر (مع مَن تشترك)، وليست نموذج خدمة.

٣. في أيّ نموذجٍ يدير الزبون أقلّ عددٍ من الطبقات؟

أ)داخل المؤسّسة
ب)IaaS
ج)PaaS
د)SaaS

التعليل: في SaaS يدير المزوّد كلّ شيءٍ حتى التطبيق؛ ولا يبقى للزبون إلّا بياناته وحساباته وأجهزته.
لماذا ليست الخيارات الأخرى: «أ» الزبون يدير كلّ الطبقات، حتى المبنى. «ب» الزبون ما زال يدير نظام التشغيل وبيئة التشغيل والتطبيقات والبيانات. «ج» الزبون ما زال يدير التطبيق والبيانات.

٤. عدّة جامعاتٍ تتشارك بنيةً سحابيّة واحدة بُنيت لمتطلّباتها الأكاديميّة والقانونيّة المشتركة. هذه:

أ)سحابة عامّة
ب)سحابة خاصّة
ج)سحابة مجتمعيّة
د)سحابة هجينة

التعليل: السحابة المجتمعيّة تتشاركها مجموعةٌ محدّدة من المؤسّسات لها اهتماماتٌ مشتركة (الرسالة، الامتثال، المتطلّبات الأمنيّة).
لماذا ليست الخيارات الأخرى: «أ» مفتوحةٌ لـأيّ زبون، لا لمجموعةٍ محدّدة. «ب» تخدم مؤسّسةً واحدة فقط. «د» تعني ربط نموذجين مختلفين، مثل خاصّة + عامّة.

٥. الخدمة المكافئة في Microsoft Azure لخدمة Amazon S3 (تخزين الكائنات) هي:

أ)Azure Functions
ب)Blob Storage
ج)Microsoft Entra ID
د)AKS

التعليل: Amazon S3 ⇄ Azure Blob Storage ⇄ Google Cloud Storage — الثلاثة تخزين كائنات.
لماذا ليست الخيارات الأخرى: «أ» دوالّ بلا خادم (≈ AWS Lambda). «ج» إدارة الهويّة والصلاحيّات (≈ AWS IAM). «د» Kubernetes مُدار (≈ AWS EKS).

٦. حسب نموذج المسؤوليّة المشتركة، أيّ بندٍ هو مسؤوليّة الزبون دائمًا في كلّ نماذج الخدمة؟

أ)تحديث المشرف الافتراضيّ
ب)الأمن الفعليّ لمركز البيانات
ج)تصنيف بياناته وحمايتها
د)استبدال الأقراص التالفة

التعليل: البيانات والهويّات (الحسابات وكلمات المرور والتحقّق المتعدّد) وأجهزة المستخدمين تبقى على الزبون في IaaS وPaaS وSaaS.
لماذا ليست الخيارات الأخرى: «أ» الطبقة الافتراضيّة للمزوّد في النماذج الثلاثة. «ب» الحرّاس والكاميرات والدخول إلى المبنى على المزوّد. «د» العتاد الفعليّ دائمًا على المزوّد.

٧. «جهازٌ فعليّ واحد يستضيف أجهزةً افتراضيّة لزبائن كثيرين مختلفين.» أيّ خاصيّةٍ هذه؟

أ)الوصول الواسع عبر الشبكة
ب)تجميع الموارد (تعدّد المستأجرين)
ج)الخدمة الذاتيّة عند الطلب
د)الخدمة المَقيسة

التعليل: تجميع الموارد يعني أنّ موارد المزوّد تخدم عدّة مستهلكين (نموذج تعدّد المستأجرين) وتُوزَّع ديناميكيًّا.
لماذا ليست الخيارات الأخرى: «أ» تتعلّق بالوصول إلى الخدمة عبر الشبكة من أنواع أجهزةٍ كثيرة. «ج» تتعلّق بإنشاء الموارد بنفسك دون طلبٍ من مسؤول. «د» تتعلّق بقياس الاستهلاك ومحاسبته.

٨. في اختراق Capital One (٢٠١٩) سُرق نحو ١٠٠ مليون سجلّ زبونٍ من بياناتٍ محفوظة في AWS. السبب الجذريّ كان:

أ)خللٌ في أمن مراكز بيانات AWS
ب)إعدادٌ خاطئ على موارد يشغّلها المصرف نفسه في AWS
ج)كارثةٌ طبيعيّة في مركز البيانات
د)ثغرةٌ في كود خدمة S3

التعليل: استغلّ المهاجم جدار حماية تطبيقات ويب مضبوطًا خطأً على خوادم المصرف نفسه وصلاحيّاتٍ أوسع من اللازم. لم تُخترق بنية AWS — إخفاقٌ نموذجيّ في «الأمن داخل السحابة».
لماذا ليست الخيارات الأخرى: «أ» لم تُخترق أيّ منشأةٍ أو عتادٍ لـ AWS. «ج» لم يكن هناك أيّ حدثٍ فعليّ. «د» خدمة S3 نفسها عملت كما صُمّمت؛ والصلاحيّات كانت من إعداد الزبون.

٩. جامعةٌ تحتفظ بسجلّات الطلبة على خوادمها، وتنقل موقعها العامّ إلى سحابةٍ عامّة، وتربطهما بـ VPN. هذه:

أ)سحابة خاصّة
ب)سحابة هجينة
ج)سحابة مجتمعيّة
د)سحابة عامّة

التعليل: نموذجا نشرٍ مختلفان (خاصّ + عامّ) مرتبطان ويُستخدمان معًا = هجينة. ووصلة VPN تصبح سطح هجومٍ مهمًّا.
لماذا ليست الخيارات الأخرى: «أ» ستُبقي كلّ شيء على بنية الجامعة نفسها. «ج» تحتاج عدّة مؤسّساتٍ تتشارك بنيةً واحدة. «د» ستضع كلّ شيء على البنية المشتركة للمزوّد.

١٠. أُعلنت ثغرةٌ خطيرة في نواة Linux. مَن يجب أن يحدّثها لتطبيقٍ يعمل على Google App Engine (PaaS)؟

أ)الزبون، بالدخول إلى الخادم
ب)المزوّد (Google)
ج)لا أحد — لا نظام تشغيل في PaaS
د)مستخدمو التطبيق

التعليل: في PaaS يدير المزوّد نظام التشغيل وبيئة التشغيل، فـ Google تحدّث النواة. ويبقى على الزبون تأمين كوده ومكتباته الخارجيّة.
لماذا ليست الخيارات الأخرى: «أ» صحيحٌ في IaaS (مثل EC2)، لا في PaaS. «ج» كلّ منصّةٍ تعمل على نظام تشغيل؛ لكنّك لا تديره. «د» المستخدمون لا يصلون إلى المنصّة أصلًا.

صح أو خطأ

خطأ

التعليل: مزوّد SaaS يدير ويحدّث كلّ شيءٍ حتى التطبيق. والزبون يدير البيانات والحسابات والأجهزة.

٢. الانتقال إلى السحابة ينقل كلّ المسؤوليّة الأمنيّة إلى المزوّد.

خطأ

التعليل: المسؤوليّة مشتركة. البيانات والهويّات والإعدادات تبقى على الزبون دائمًا — وهناك تحدث أغلب الاختراقات الحقيقيّة.

٣. السحابة الهجينة تربط بيئةً خاصّة بسحابةٍ عامّة لتعملا معًا.

صح

التعليل: هذا معنى الهجينة عند NIST: بنيتان مختلفتان أو أكثر مرتبطتان معًا.

٤. المرونة السريعة تعني إمكان تكبير السعة وتصغيرها بسرعة، وغالبًا تلقائيًّا.

صح

التعليل: تبدو السعة للمستهلك غالبًا بلا حدود، ويمكن إضافتها أو تحريرها في أيّ وقت.

٥. خادمٌ في غرفة خوادم الجامعة لا تحصل عليه إلّا بطلبٍ مكتوب إلى قسم تقنية المعلومات هو خدمةٌ سحابيّة حسب NIST.

أسئلة قصيرة — إجابات نموذجيّة

١. اكتب تعريف NIST للحوسبة السحابيّة بأسلوبك (٢–٣ أسطر)، واذكر الخصائص الأساسيّة الخمس.

الإجابة النموذجيّة: الحوسبة السحابيّة تتيح الوصول عند الطلب، عبر الشبكة، إلى مجمّعٍ مشترك من الموارد الحاسوبيّة القابلة للتهيئة، تُحجز وتُحرَّر بسرعة وبأقلّ جهدٍ إداريّ. الخصائص: ① خدمة ذاتيّة عند الطلب ② وصول واسع عبر الشبكة ③ تجميع الموارد ④ مرونة سريعة ⑤ خدمة مَقيسة.

دليل التصحيح: درجاتٌ على: «عند الطلب»، «عبر الشبكة»، «مجمّع مشترك»، «حجز/تحرير سريع» في التعريف؛ ودرجةٌ لكلّ خاصيّة.

٢. أعطِ مثالًا واحدًا لكلٍّ من IaaS وPaaS وSaaS، واذكر لكلٍّ منها مهمّةً أمنيّة تبقى على الزبون.

الإجابة النموذجيّة: IaaS — AWS EC2: تحديث نظام التشغيل الضيف وتقييد مجموعة الأمان (مثلًا لا SSH مفتوح لـ 0.0.0.0/0). PaaS — Google App Engine: تأمين كودك وتحديث المكتبات الخارجيّة، وضبط مَن يستطيع النشر. SaaS — Gmail أو Microsoft 365: كلمة مرورٍ قويّة + التحقّق بخطوتين، وضبط مشاركة المستندات.

دليل التصحيح: يُقبل أيّ مثالٍ صحيح إذا طابقت مهمّة الزبون النموذج: عمل نظام التشغيل في IaaS فقط؛ الكود والمكتبات في PaaS؛ الحسابات والبيانات والمشاركة في الثلاثة.

٣. مستشفى في بغداد يريد حفظ سجلّات المرضى وتشغيل موقعٍ عامّ لحجز المواعيد. اقترح نموذج نشرٍ وعلّل اختيارك من الناحية الأمنيّة.

الإجابة النموذجيّة: سحابة هجينة. سجلّات المرضى (بياناتٌ صحّيّة شديدة الحساسيّة، متطلّباتٌ قانونيّة، ويُفضَّل بقاؤها في العراق) تبقى في سحابةٍ خاصّة يتحكّم بها المستشفى. وموقع الحجز العامّ يعمل على سحابةٍ عامّة للتوفّر والتوسّع، ولا يحفظ إلّا بياناتٍ قليلة (الاسم، الموعد). التركيز الأمنيّ: وصلةٌ محميّة بين الاثنين (VPN، هويّة قويّة، أقلّ صلاحيّة)، وتشفير البيانات أثناء النقل والتخزين، والسجلّات والمراقبة في الجهتين.

دليل التصحيح: إجابة «عامّة فقط» تنال درجةً جزئيّة إذا عالجت موقع البيانات والتشفير والصلاحيّات؛ وإجابة «خاصّة فقط» إذا عالجت توفّر الموقع العامّ.
